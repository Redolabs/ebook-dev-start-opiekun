`Request` i `Response` są przepisane dobrze, a `Response::json()` zbudowane tak, jak chce książka. Ale gałąź wyszła ze starego `main` sprzed merge PR #1, więc GitHub pokazuje konflikt, a formularza POST z zadania rozdziału 2 nie ma w żadnym commicie.

## Zadanie
- Rozdział 2, `isPost()`: zrobione, korzysta z `$this->method` i `===`.
- Rozdział 2, formularz POST z polem `title` i wypisanie `input('title')`: brak. Nie ma go ani w obecnym `index.php`, ani w żadnym z dwóch commitów. W review PR #1 odłożyliśmy to na ten PR.
- Rozdział 3, `Response::json(array $data): self`: zrobione, statyczna, przez `header()`, nie przez `header()` z PHP.
- Rozdział 3, `/api` zwraca `['ok' => true]`: zrobione, gałąź `elseif` przed `else` jak w rozwiązaniu.

- `php -S` i `curl`: nie udało się sprawdzić (tryb auto nie pozwala uruchamiać kodu ucznia). Z czytania kodu `/`, `/stara`, `/api` i 404 powinny działać.

- Porównanie z `origin/main`: `core/Request.php` na gałęzi jest bajt w bajt taki sam jak ten zmergowany z PR #1.

## Komentarz do PR (idzie do ucznia)

`Request` i `Response` są przepisane bez błędów, a `Response::json()` zbudowałeś tak samo jak `redirect()`: statyczna metoda, która zwraca `self` i ustawia nagłówek przez własne `header()`, nie przez funkcję PHP. To jest dokładnie to, o co prosił rozdział 3. Gałąź `/api` stoi przed `else`, więc 404 dalej działa dla reszty adresów.

### Do poprawy przed merge
1. GitHub pokazuje konflikt („This branch has conflicts that must be resolved”). Gałąź `feature/request-response` założyłeś ze starego `main`, sprzed merge PR #1: są na niej jeszcze `vendor/` i `hello.php` z małej litery, a nie ma `.gitignore` ani `Task.php`. W rytuale z rozdziału 1 po merge jest krok `git switch main && git pull`, i dopiero potem nowa gałąź. Teraz napraw to tak: `git switch main`, `git pull`, `git switch feature/request-response`, `git merge main`. Git zgłosi konflikt w `public/index.php`; zostaw w nim swoją wersję z rozdziału 3 (bez `Task`), usuń znaczniki `<<<<<<<`, `=======`, `>>>>>>>`, potem `git add`, `git commit` i `git push`. Jeśli się zablokujesz, napisz, przejdziemy to razem.
2. `public/index.php:16`: nie ma formularza z zadania rozdziału 2 („mały formularz z `method="post"` i polem `title`, wypisz `input('title')`”). Nie ma go też w żadnym commicie, a `isPost()` nigdzie nie jest używany. Dołóż go pod osobnym adresem, np. `/formularz`, jako kolejny `elseif`: treść `Response` to zwykły string, więc HTML formularza i wynik `input('title')` możesz tam złożyć. Sprawdź dwie rzeczy: po wysłaniu formularza widzisz wpisany tytuł, a przy zwykłym wejściu na `/formularz` `input('title')` daje `null`.
3. Opis i tytuł PR: tytuł „Feature/request response” wygenerował GitHub, a opis to komunikat commita. Wzór z rozdziału 1 to dwie linijki: „Co zrobiłem” i „Jak sprawdzić”. Tutaj „Jak sprawdzić” to lista adresów z rozdziału 3 (`/`, `/stara`, `/api`, cokolwiek innego) i co ma być widać pod każdym. Tytuł np. „Rozdziały 2 i 3: Request i Response”. Bez tego nie zatwierdzę, bo to część zadania, nie dodatek.
